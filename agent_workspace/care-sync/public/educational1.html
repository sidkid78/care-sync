How Care-Sync Turns Raw Data into Caregiving Insights

1. The Magic of the AI Pipeline

In modern software architecture, we are moving beyond static applications into the era of Agentic AI. For a developer or systems student, "Agentic AI" refers to a system designed to act as an autonomous agent—taking a high-level goal (such as "summarize this doctor's visit") and executing a complex, multi-step pipeline to achieve it without constant human intervention.

This document serves as an Educational Workflow Narrative. It is designed to pull back the curtain on Care-Sync, a platform that helps families coordinate care for loved ones. While the user experience is seamless, the backend is a sophisticated orchestration of distributed services that transform raw, messy data into life-saving insights.

Learning Objectives

  • Understanding Asynchronous Processing: Learn why complex AI tasks are offloaded to background queues to maintain system responsiveness.
  • Identifying External APIs: Discover how platforms integrate specialized AI services (Gemini 2.5 Flash) into a unified workflow.
  • Grasping Data Security: Understand the technical guardrails, such as encryption standards and integrity checks, required for sensitive health information.

While the app's interface is designed for simplicity, the underlying architecture is a masterclass in orchestrating complex, distributed systems to solve real-world problems.

2. The "Relay Race" Pattern

In a typical web application, clicking a button yields an instant result. However, AI tasks—such as processing a ten-minute medical recording—are computationally expensive and time-consuming. If the application waited for the AI to finish, the user interface would freeze. To solve this, Care-Sync utilizes asynchronous processing.

Architecturally, we treat this as a "Relay Race." One component starts the job and passes a "baton" (a message) to a specialized runner (a worker service). This allows the main application to remain responsive while the heavy lifting happens in the background.

FIG 2.0: SYSTEM ORCHESTRATION

The Pipeline Relay

Stage Name Key Component Architectural Rationale
Initiation Supabase Edge Functions Acts as the starter pistol. Provides immediate feedback, ensuring low latency.
Orchestration Message Queues (AWS SQS) The "Baton" holder. Decouples request from execution to scale horizontally.
Execution AI Worker Services (Lambda/ECS) The heavy lifters. Serverless logic scaling only when work is present.
Delivery Supabase DB & Realtime The finish line. Results pushed via WebSockets updating UI without refresh.

By breaking the workflow into these decoupled stages, the platform ensures that the "Execution" stage never becomes a bottleneck for the rest of the system.

3. Workflow Deep Dive: The Doctor Digest

The "Doctor Digest" is a hero feature that transforms a chaotic medical appointment into an organized care plan. Here is the architectural journey of that data:

  1. Secure Recording: The caregiver records audio via the Web Audio API.
  2. Pre-signed URL Upload: Client requests a pre-signed URL to upload directly to Supabase Storage with temporary permissions.
  3. Multimodal Processing (Gemini 2.5 Flash): A worker service decrypts locally encrypted data (via KMS) and passes audio directly to Gemini.
  4. Clinical Extraction: The model filters for clinical facts using a specialized medical prompt in the same pass.
  5. Action Item Extraction: AI formats specific tasks as structured JSON data.

4. Med-Cabinet Scanner: Hybrid Intelligence

ALERT: INTERACTION

The Med-Cabinet Scanner represents Hybrid Intelligence. It combines unstructured data (images), structured medical databases (OpenFDA), and agentic logic.

  • INPUT OCR Processing: Using Gemini 2.5 Flash to extract text from pixels.
  • PROCESS Drug Identification: NLP isolates drug names and queries OpenFDA to normalize data.
  • AGENTIC CORE Conflict System: Queries user Supabase profile to check contraindications against allergies and existing meds.

This multi-checkpoint approach ensures every insight is grounded in verified medical databases, significantly safer than a single AI "guess."

5. The Invisible Shield

Care-Sync treats security not as a feature, but as the foundation. We employ multiple layers of protection.

Data in Transit

TLS 1.3

Encrypts motion to prevent "man-in-the-middle" attacks.

Data at Rest

AES-256

Scrambles stored data via secure KMS.

Integrity

SHA256 Checksum

Digital fingerprint against tampering.

The "Vault": Client-Side Encryption

For sensitive documents, encryption happens on the user's phone (Web Crypto API + PBKDF2) before data reaches our servers. Even administrators cannot read the files. We simply host a "locked box" that only authorized family members can open.
